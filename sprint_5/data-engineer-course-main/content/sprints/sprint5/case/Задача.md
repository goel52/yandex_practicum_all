## 1. Постановка задачи.
Бизнес растет. Не так давно в компании приняли решение запустить собственную доставку блюд из ресторанов. Для этого в компании разработали три системы: 
- подсистема обработки заказов
- подсистема оплат баллами
- подсистема курьерской доставки

Вам предстоит построить хранилище данных, собрав данные из всех трех источников.

### 1.1. Задача #1.
Первая и главная на текущий момент потребность бизнеса - организовать взаиморасчеты с ресторанами.
Взаиморасчеты должны строиться на данных из подсистемы обработки заказов, а так же на данных по оплатам бонусами.

Бизнес-процесс построен таким образом, что наша компания принимает оплаты от клиентов на свой счет, а в начале следующего месяца (не позднее 10 рабочих дней) переводит необходимые суммы ресторанам-партнерам. Соответственно, по окончании каждого месяца компания должна подготовить акт, в который включить сумму задолженности перед ресторанами-партнерами. Далее бизнес согласовывает суммы с партнерами и выплачивает ресторанам.

Ваша задача - обеспечить:
- расчет общих сумм задолженности перед ресторанами-партнерами. Т.е. построить витрину, на основе которой можно будет посчитать задолженности.
- обеспечить детализацию по заказам, если возникнут вопросы со стороны партнеров.


### 1.2. Общая цель создания хранилища.
Вы должны помнить, что сейчас решаете локальную задачу. Но хранилище надо проектировать с учетом того, что аналитика (и, соответственно, ЗД в компании будет активно развиваться). Например, следующим большим шагом станет добавление в ХД информации из подсистемы курьерской службы.


# 2. Исходные данные.

В этом разделе приведено описание входных данных из подсистем-источников.

### 2.1. Обработка заказов.
Подсистема обработки заказов работает на mongodb - документо-ориентированная NoSQL базе данных. Вам предстоит забирать данные посредством CDC через WAL.
Данные о заказе - это единый документ, структура описана ниже.

### 2.2. Система оплаты бонусами.
В приложении есть своя собственная система оплаты бонусами. В качестве БД используется PostgreSQL. Вам надо разработать способ забора данных из PG в вашу СУБД.

### 2.3. Курьерсоке приложение.
Данные курьерского приложения доступны через API. Вам необходимо будет разработать программу на python, чтобы забирать данные из API.

## 3. Процесс решения.
Разберем шаги, которые необходимо предпринять для реализации решения.

### 3.1. Выясняем требования.
1. Читаем описание задачи и изучаем ссылки на документацию
2. Собираем более детально требования по задаче у людей с соответствующими ролями в команде и фиксируем эти требования для однозначного понимания между заказчиком и исполнителем. (за малый промежуток времени требования могут незначительно измениться, утратить силу договоренности, у исполнителя и заказчика разное понимание одного и того же термина и прочее).
3. Уточняем какие сервисы используют данные из текущей БД и определяем их критичность, фиксируем этот импакт.
4. Проверяем наличие соответствующих доступов и прав на создание, изменение, удаление. Если доступов нет, то запрашиваем необходимые доступы.
