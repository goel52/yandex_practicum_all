# de07050401 — статическая проверка портрета контактов

`POST /api/v1/checks/de07050401_connection_interests/`

DTO сохранён: `student_id: str`, `student_solution: str`. В `student_solution`
передаётся JSON-строка с содержимым `connection_interests.py`, `run_jobs.sh`,
`dag.py`. Клиент собирает пакет автоматически. Ответ — `status` и `message`,
при успехе с кодом `qHZKWImPxO` из урока.

## Проверяемая структура

Код разбирается через `ast.parse`; импорт и исполнение студенческих файлов,
`main`, shell и DAG не выполняются. Spark для этой проверки не используется.

- В `run_jobs.sh`: spark-submit для connection_interests.py, дата 2022-05-25,
  глубина 7, шесть аргументов и пути продового слоя. Текущий снапшот тегов
  допускается в `/user/prod/` или общем источнике `/user/master/`.
- В DAG: запуск за 7 дней с личными путями и зависимость от user_interests
  за согласованные дату/глубину/пути; отсутствие циклов. Поддерживаются
  SparkSubmitOperator/BashOperator, >>/<<, списки, set_upstream/set_downstream.
- В Python: шесть присваиваний из sys.argv, построение путей за depth дней,
  выражения чтения сообщений/интересов/актуальных тегов, история подписок до
  даты расчёта, фильтры личных сообщений и сообщений каналов, запись result
  в output_base_path/date=date.
- В функциях алгоритма: обе стороны контакта и дедупликация, разворачивание
  top-слотов реакций, countDistinct(contact_id), группировка user_id/tag,
  порядок tag_count DESC/tag DESC, row_number и pivot на 1/2/3, соединение
  с verified_tags, count появлений тегов и full outer объединение результатов.

Проверка рассчитана на структуру имеющегося авторского прекода:
`main`, `input_event_paths`, `get_contacts`, `get_contact_interests`,
`get_subs_interests`, `join_result`, `tag_columns`. В main сохраняются имена
переменных из этого шаблона. SQL-фильтры ожидаются строковыми выражениями
where/filter. Другая, семантически эквивалентная организация кода может не
пройти эту ограниченную статическую проверку.

## Границы проверки

Успех означает наличие ожидаемых конструкций AST, а не доказанную корректность
расчёта. Не проверяются реальные значения десяти выходных колонок, null,
кратности строк, фактическая фильтрация периодов, исполнение всех ветвей,
ошибки времени выполнения и фактическая запись Parquet. Наличие отдельных
конструкций также не доказывает, что они включены в действующий путь расчёта.
Дополнительные исполняемые инструкции не запускаются и не считаются
проверенными. Статический анализ не является аудитом безопасности кода.

Временных Parquet-файлов, subprocess, SparkContext и отдельной JVM здесь нет.
Песочница для исполнения студенческой джобы этой проверке больше не нужна,
поскольку код не исполняется. Другие проверки сервиса со Spark не менялись.
Spark запускается лениво при вызове соответствующей зависимости, а не при
импорте всего приложения.

## Тесты без JVM

Из корня `de-sprint-7-checks`:

```bash
PYTHONPATH=src venv/bin/python -m pytest \
  tests/test_de07050401_connection_interests.py \
  tests/unit/test_connection_artifacts.py -q
```

Отдельный тест запрещает запуск процессов при проверке запроса; другой
проверяет, что инструкции записи файла в студенческом коде не исполняются.
JDK, запущенный Spark, Airflow, HDFS и доступ к локальным сокетам для этого
набора не нужны. Полное приложение всё ещё имеет Python-зависимости остальных
Spark-проверок, а полный pytest включает их динамические тесты.
