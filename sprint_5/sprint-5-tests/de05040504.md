### <Задание 4 в Docker. Заведите таблицу для записи текущего положения>

Чтобы не скачивать повторно одни и те же данные из таблицы `outbox` при повторяющихся запусках DAG, нужна таблица, в которой будет сохраняться текущий прогресс. 

В качестве курсора, то есть показателя прогресса заливки данных, будем использовать `id` последней сохранённой записи. Работать эта схема будет только если сохранять данные в PostgreSQL, то есть в хранилище данных, в порядке увеличения `id`. 

Заведите таблицу для хранения текущего курсора загруженных данных. Назовите её `stg.srv_wf_settings`. Таблица должна состоять из таких полей:

- `id` — суррогатный `id`-записи, первичный ключ, автоинкремент.
- `workflow_key` — ключ задачи, которая сохраняет свою отметку о загрузке данных. Таких ключей может быть несколько.
- `workflow_settings` — произвольный набор параметров. Его структура может быть уникальной для каждой задачи, поэтому рекомендуем использовать текстовый формат или JSON.

- ТУП
    
    Таблица для сохранения прогресса готова! Можно переходить к переносу данных из `outbox`.
    
- Авторское решение
    
    ```sql
    CREATE TABLE IF NOT EXISTS stg.srv_wf_settings (
        id int NOT NULL PRIMARY KEY GENERATED ALWAYS AS IDENTITY,
        workflow_key varchar NOT NULL UNIQUE,
        workflow_settings JSON NOT NULL
    );
    ```
